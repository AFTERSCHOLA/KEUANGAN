### 7.1 Handoff F.1 — R3.1 localStorage hydration race (1 failure)

**Symptom:** `r3-verify.spec.js:97` — `TypeError: Cannot read
properties of undefined (reading 'wa')` at line 111: `expect(siswa[0].wa).toBe('6281234567890')`.

**Repro:**
- Passes in isolation with `npm run db:reset && npx playwright test
  tests/r3-verify.spec.js --workers=1 --project=default -g "R3.1"`.
- Fails when `auth-login-page.spec.js` runs first, OR in the full
  default-project run.

**Evidence (from baseline error-context.md):** The page snapshot at
`test-results/r3-verify-R3-1-siswa-WA-normalizes-to-62-format-on-blur-default/error-context.md:82-100`
shows the siswa WAS saved successfully (table row "Siswa R3 Sim 482449",
WA link `6281234567890` already normalized to 62). But
`getStoreJson(page, 'siswa')` returns `[]`.

**Suspected cause:** A hydration race between `writeRemote('siswa', ...)`
returning and the SiswaTable re-render populating localStorage. The
test reads localStorage directly (`page.evaluate(() =>
localStorage.getItem('afterschola_v4_siswa'))`), bypassing the
React state. The cache might be populated only after the next
notification tick.

**Proposed bounded plan:** R3.1's diagnostic:
- Add a `await page.waitForResponse('**/api/siswa.php')` before the
  localStorage read, OR
- Replace `getStoreJson(page, 'siswa')` with
  `await page.locator('tr', { hasText: SISWA }).waitFor()` and read
  the WA from the row's link (`await
  page.locator('tr', { hasText: SISWA }).getByRole('link').first().getAttribute('href')`).

**Estimated effort:** 30 minutes.
