# Deploy Bundle (`deploy/`)

**Status:** Implemented — see `scripts/build-deploy.cjs`. The `deploy/` directory is now **generated**, never hand-edited.
**Purpose:** Define how the bundle that lands on cPanel is produced, what is in it, what is NOT in it (and where those things live instead), and how the parity check keeps it from drifting.

---

## 1. Decision Set

| # | Decision | Status |
|---|---|---|
| D1 | `deploy/` is generated by `npm run build:deploy`, never edited by hand | Locked |
| D2 | Build is idempotent and re-runnable; recovery for any drift = re-run the same command | Locked |
| D3 | `deploy/api/`, `deploy/auth/`, `deploy/bin/`, `deploy/bootstrap.php`, `deploy/config.example.php`, `deploy/schema.sql`, `deploy/.htaccess` are gitignored (mirror artifacts) | Locked |
| D4 | Vite outputs (`index.html`, `assets/`, `manifest.webmanifest`, `registerSW.js`, `sw.js`, `pwa/`, `workbox-*.js`) are tracked so PRs show what cPanel will serve | Locked |
| D5 | Parity check is a hard gate: pre-check is diagnostic (prints the diff, continues), post-check is authoritative (fails the build if the mirror dropped a file) | Locked |
| D6 | `private/` is NEVER in `deploy/` — it's outside the cPanel document root per `PRODUCTION_PLAN.md` §11 | Locked |
| D7 | `config.php` is NEVER in `deploy/` — operator writes it on the server from `config.example.php` after upload | Locked |
| D8 | `server/` is the canonical source of truth. `src/` is handled by Vite. The build script reads them; it never edits them | Locked |

## 2. Build flow

```text
npm run build:deploy
  │
  ├─ 1. Node ≥ 18 check
  ├─ 2. vite build  (→ dist/)
  ├─ 3. pre-check parity (server/ vs current deploy/)   ← diagnostic
  ├─ 4. wipe deploy/api, deploy/auth, deploy/bin,
  │         deploy/bootstrap.php, deploy/schema.sql
  ├─ 5. mirror:
  │       server/api/        →  deploy/api/
  │       server/auth/       →  deploy/auth/
  │       server/bin/        →  deploy/bin/
  │       server/validation/ →  deploy/api/validation/   (relative require paths)
  │       server/bootstrap.php        →  deploy/bootstrap.php
  │       server/config.example.php   →  deploy/config.example.php
  │       server/schema.sql           →  deploy/schema.sql
  ├─ 6. copy dist/* → deploy/   (overwrites Vite outputs)
  ├─ 7. write deploy/.htaccess  (blocks private/, *.sql, *.log, config.php, …)
  │         write deploy/.gitignore (ignores the mirror artifacts)
  └─ 8. post-check parity (server/ vs new deploy/)   ← HARD GATE
```

### Flags

- `--dry-run` — print the mirror plan without writing anything; exits 0.
- `--skip-vite` — skip step 2 (use existing `dist/`). Useful when iterating on the script after a manual Vite build.

### Re-run is the recovery path

If the pre-check prints a diff, just re-run `npm run build:deploy`. It will wipe the stale files and copy fresh ones from `server/`. If the post-check fails, that's a bug in `scripts/build-deploy.cjs` itself — the mirror step dropped or duplicated a file.

## 3. What ends up in `deploy/` after a clean build

```text
  deploy/
    .gitignore              ← generated (ignores the mirror artifacts)
    .htaccess               ← generated (blocks private/, *.sql, *.log, config.php, …)
    index.html              ← Vite output, TRACKED
    manifest.webmanifest    ← Vite output, TRACKED
    registerSW.js           ← Vite output, TRACKED
    sw.js                   ← Vite output, TRACKED
    workbox-*.js            ← Vite output, TRACKED
    assets/                 ← Vite output, TRACKED (hashed names; rebuild-only)
    pwa/                    ← Vite output, TRACKED (icon + manifest)

    api/                    ← mirror of server/api/ — GITIGNORED
      _master.php
      absensi.php, sppPayments.php, honorPayments.php, read.php, sync.php
      sekolah.php, trainer.php, siswa.php, cabang.php, settings.php
      invoices.php, invoices-generate.php
      backup-create.php, backup-download.php, backup-list.php, restore.php
      users.php
      validation/
        entities.php        ← mirrored from server/validation/

    auth/                   ← mirror of server/auth/ — GITIGNORED
      authorize.php
      session.php

    bin/                    ← mirror of server/bin/ — GITIGNORED
      create-superadmin.php
      generate-invoices.php

    bootstrap.php           ← mirror of server/bootstrap.php — GITIGNORED
    config.example.php      ← mirror of server/config.example.php — GITIGNORED
    schema.sql              ← mirror of server/schema.sql — GITIGNORED
```

NOT in `deploy/` (and never will be):
- `config.php` — created on the server by the operator from `config.example.php`. Real DSN/credentials never enter the repo.
- `private/` — uploads, backups, logs live **outside** the cPanel document root per `PRODUCTION_PLAN.md` §11.
- Anything from `server/tests/`, `server/validation/` except as listed above (tests are not deployed; validation is mirrored *into* `deploy/api/validation/`).

## 4. Operator runbook (after `npm run build:deploy` exits 0)

1. Upload everything under `deploy/` to the cPanel document root (e.g. `/home/<user>/public_html/`). Preserve directory structure.
2. Create `config.php` in the document root:
   ```bash
   cp config.example.php config.php
   ```
   Edit `config.php` with the real DSN (`mysql:host=...;dbname=...;charset=utf8mb4`), username, password, and set `'environment' => 'production'`, `'session_secure' => true`.
3. Import the schema (first deploy only):
   - phpMyAdmin → Import → upload `schema.sql` → Go. (For incremental updates once M6.1 ships, apply ordered migrations instead.)
4. Create `private/` outside the document root:
   ```bash
   mkdir -p /home/<user>/private/uploads
   mkdir -p /home/<user>/private/backups
   mkdir -p /home/<user>/private/logs
   ```
   Adjust the `private/` paths in `config.php` (when those settings are added in a future milestone).
5. Bootstrap the first Superadmin:
   ```bash
   php bin/create-superadmin.php --username=<name> --display-name=<name> --password=<temp-password>
   ```
   Log in via the UI, change the password on first login (`MustChangePasswordPage` enforces this — see `PRODUCTION_MILESTONES.md` M2.4).

## 5. Verification

| # | Check | Pass condition |
|---|---|---|
| 1 | Build exits 0 | `npm run build:deploy` → "Build OK: N PHP files mirrored, M Vite assets copied, .htaccess written." |
| 2 | Pre-check on a clean state | "pre-check: clean." |
| 3 | Pre-check on a drifted state | Diff printed, mirror rebuilds it, build OK |
| 4 | Post-check parity | "post-check: verifying new deploy/ against server/ …" (silent if clean, hard-fail if not) |
| 5 | Generated artifacts gitignored | `git status` after a build shows the Vite outputs as modified, mirror files absent |
| 6 | 401 (not 404) on cPanel | `GET /api/users.php` with no session → 401 (route exists; auth blocks) |
| 7 | Roundtrip on cPanel | Login as superadmin → `POST /api/users.php` with a trainer payload → 201 → restart PHP → `GET /api/read.php?entity=trainer` still returns the row |

Check 7 is the exact bug `docs/IMPLEMENTATION_PLAN.md` Part 4 and your team's report describes — "refresh loses data." This build makes it impossible to ship.
